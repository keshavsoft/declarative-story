Definitions Part 1 of 2

Definitions Hold Clean Collections of Instructions

Earlier versions carried inline options maps inside definitions.json. Starting from the decoupled contract, each variation stays minimal — just one baseFromSpec plus an ordered instructions list.

table Variations (definitions v5)

{
  "table": {
    "headerOnly":     { "baseFromSpec": "tableHeaderOnly", "instructions": ["buildColgroup", "buildHeader"] },
    "simple":         { "baseFromSpec": "tableSimple",     "instructions": ["buildColgroup", "buildHeader", "buildBody"] },
    "withFooter":     { "baseFromSpec": "tableWithFooter", "instructions": ["buildColgroup", "buildHeader", "buildFooter", "buildBody"] },
    "bodyOnly":       { "baseFromSpec": "tableBodyOnly",   "instructions": ["buildBody"] },
    "simpleSortable": { "baseFromSpec": "tableSimple",     "instructions": ["buildColgroup", "buildHeaderClickable", "buildBody"] }
  }
}

Optional features (like search or serial columns) are passed by the caller at runtime and resolved directly into keys inside declarative-instructions.
