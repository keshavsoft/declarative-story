Why Definitions Must Name an Instruction, Never a Spec

When building clickable table headers (table.simpleSortable), placing the spec key directly in definitions.json crashed at runtime — proving why cross-repo fail-safe checks matter.

Broken: Spec Key in Definitions

"instructions": [
  "buildColgroup",
  "tableHeaderClickable",  // exists only in spec!
  "buildBody"
]

Runner looks up instructions["tableHeaderClickable"] → undefined → throws TypeError: Cannot read properties of undefined (reading 'type').

Fixed: Two Clean JSON Updates

// 1. instructions v3:
"buildHeaderClickable": { ..., "templateKey": "tableHeaderClickable" }

// 2. definitions v5:
"instructions": ["buildColgroup", "buildHeaderClickable", "buildBody"]

Zero JavaScript rendering logic touched — sortable headers (⇅) rendered immediately!
