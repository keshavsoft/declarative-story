Tier 4 • Component Contracts & Options

The Crown of the Architecture: declarative-definitions

How high-level component blueprints tie base specifications, assembly instructions, and feature options (search frames, serial numbers) into production-ready UI contracts.

1. What is a Component Definition?

By the time we reach Tier 4, we have:

  • A dictionary of valid tags and attributes (declarative-tags).
  • Pure HTML element blueprints (declarative-spec).
  • Transformation rules (declarative-instructions).

declarative-definitions is the master contract. It tells the compiler: *"To build a `table.simple`, take `tableSimple` from `declarative-spec`, execute `buildColgroup`, `buildHeader`, and `buildBody` from `declarative-instructions`, and initialize search options."*

2. The Blueprint Contract

The blueprint declares options like search input frames and row serial numbering: 

{
  "table": {
    "simple": {
      "baseFromSpec": "tableSimple",
      "instructions": [
        "buildColgroup",
        "buildHeader",
        "buildBody"
      ],
      "options": {
        "search": {
          "initialize": "searchFrame",
          "showLabel": "searchLabel",
          "showHelper": "searchHelper",
          "showInput": "searchInput"
        },
        "serial": {
          "initialize": "serialRoot"
        }
      }
    }
  }
}
