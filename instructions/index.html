Replacing Loops with JSONPath: declarative-instructions

How declarative AST transformation rules eliminate hardcoded imperative DOM loops and allow runtime restructuring without compiler changes.

1. The Problem: Rigid Compiler Loops

Building a table in a standard compiler requires imperative JavaScript:

// Imperative legacy pattern (fragile): const thead = document.createElement('thead'); columns.forEach(col => { const th = document.createElement('th'); th.textContent = col.name; thead.appendChild(th); }); table.appendChild(thead);

If product requirements suddenly require adding a <colgroup>, or wrapping headers inside a <div class="sticky-header">, you must edit and release new compiler engine code.

declarative-instructions moves this assembly knowledge entirely into declarative data.

2. The Instruction Contract

Instead of imperative code, instructions describe four things:

  • destinationPath: JSONPath query where to mount output.
  • sourcePath: Where to read input data array ($.columns).
  • templateKey: The blueprint from declarative-spec to clone.
  • func: The transformation strategy (fromCollection, oneDimension).
{
  "buildHeader": [
    {
      "destinationPath": "$",
      "templateKey": "buildHeader",
      "type": "single"
    },
    {
      "destinationPath": "$..*[?@.attributes['data-role'] == 'headerRoot']",
      "sourcePath": "$.columns",
      "templateKey": "buildHeaderCell",
      "func": "fromCollection"
    }
  ]
}
