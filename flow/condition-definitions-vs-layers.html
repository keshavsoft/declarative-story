Fail-Safe Condition Set 3

Every Definition Must Match Both Spec & Instructions

Since Definitions sits at the top combining a base shell with a list of instructions, errors here are always cross-repo mismatches.

Conditions to Check at Definitions Level

  • Base Spec Exists: baseFromSpec is a non-empty string present in spec.json (for example, "tableSimple").
  • Every Instruction Exists: Each key in instructions: [...] is a real key in instructions.json — this catches putting a spec key like "tableHeaderClickable" inside instructions[] immediately instead of failing at runtime.
  • Target Slot Matches Base Shell: When an instruction mounts onto a data-role slot (like table-footer-row), that slot must actually exist inside spec[baseFromSpec] (tableWithFooter has it; tableSimple does not).
