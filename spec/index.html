Decoupling Blueprints from Code: declarative-spec

Why HTML element structures, CSS styling, and dynamic interpolation tokens belong in pure, serializable JSON blueprints instead of template strings.

1. What is a DOM Tag Specification?

In traditional component libraries, when you want to render a table cell or a button, you write JSX or template strings with embedded CSS classes. The moment you want to change CSS classes (e.g. from Bootstrap to Tailwind) or swap tag types, you are forced to recompile JavaScript.

In declarative-spec, every tag is stored as a pure JSON blueprint. Compilers read the prototype blueprint from spec.json, clone it, and hydrate its tokens with runtime data.

2. Blueprint Contract & Dynamic Tokens

Each entry in spec.json includes:

  • tag: The native HTML tag name (thead, td, select).
  • attributes: Serializable attributes like class, data-role, type.
  • text: Placeholders like ${columnName} replaced by the assembly pipeline.
{
  "tableSimple": {
    "tag": "table",
    "attributes": {
      "class": "table table-bordered table-striped"
    },
    "children": []
  },
  "buildBodyCell": {
    "tag": "td",
    "attributes": {
      "data-role": "bodyCell",
      "class": "px-3 py-2 text-sm text-zinc-300"
    },
    "text": "${columnName}"
  }
}
