The Grammar of Declarative UI: declarative-tags

Why every scalable declarative compiler requires an authoritative tag dictionary before writing a single line of assembly code.

1. The Problem: Silent DOM Failures

In traditional frontend applications, developers freely construct HTML tags in JSX or template strings. If someone adds an invalid attribute like disabled to a <div>, or appends children into an <input>, the browser either ignores it silently or creates malformed DOM trees.

In a declarative JSON-to-DOM compiler, this cannot be tolerated. The compiler needs a ground-truth rulebook:

  • Is this HTML tag legal?
  • Is it allowed to have text content?
  • Can it have child elements, or is it a void element?
  • Which exact attributes are legally allowed?

2. The Tag Taxonomy Contract

Every tag in tags.json has an exact, schema-enforced structure: 

{
  "colgroup": {
    "allowsTextContent": false,
    "allowsChildren": true,
    "allowedAttributes": [
      "span"
    ],
    "childTags": [
      "col"
    ]
  },
  "input": {
    "allowsTextContent": false,
    "allowsChildren": false,
    "allowedAttributes": [
      "type",
      "placeholder",
      "value",
      "name",
      "disabled",
      "readonly",
      "required",
      "list"
    ]
  }
}
